# 独立源开发小试验：一次受限JSON格式修复

状态：`prepared_not_launched`。ARIS `analyze-results` → `experiment-plan`；这是一份下一步方案，已准备12例源数据，尚未实现新runner或启动付费请求。

## 问题、假设与边界

R4.1六个目标臂完整结束后，8份新增缺失实际因整条JSON严格解析失败，有卡6份、无卡2份；另2份技术失败独立保留。全部格式失败均发生于未耗尽6次主模型上限时。唯一主要假设C1：在相同最大调用预算内，允许一次明确的生成端格式修复，可能提高可解析完成率。

支持性观察为完整分母源准确率及纠正/误改；不预设正确率提高。要排除的解释是“仅通过放宽评分器或从reason猜答案获得分数”。两臂解析器和评分完全相同，严格保留显式answer；不剪取内嵌JSON，不补语义，不翻极性。实际调用数可以不同，因此若有改善，只能归因于这一策略整体，不能宣称已隔离额外采样效应。

R4.1任务卡在CheXbench净−13、SLAKE+2且区间跨0、VQA-RAD−2且区间跨0。暂不把卡片重写或工具增强与格式修复混入同一最小试验。其余两个待验证假设是源任务匹配和生成端答案极性核对，均留待独立方案。

## 数据与暴露情况

使用`reports/cxr_action_r41_20261108/next_format_pilot/`已冻结的12题、12个源病例、12张原图；从69例既有源库中筛出23个合格单图病例后，一例一题，按`sha256('r42-format-pilot-v1:' + source_id)`顺序取前12。不读目标输入、答案、错题或成绩来选择pilot。源参考只在选择完成后做与选项的唯一文字匹配校验，未进入推理输入。

合格规则为仅1张源原图、题干显式Figure引用均能绑定该图、无预注册时间比较/历史上下文关键词；每例按source_id排序选首个合格源问题。原Figure标签通过题干前缀与图像1明确绑定，避免R4.1开发时的Figure/数字索引含糊。代码和已准备协议保留准确筛选词与排序，不在失败后另挑更易问题。

这是**已暴露源开发集**：源参考、旧源轨迹曾用于源学习和审核，部分问题需要病例语境，其参考不能替代独立临床裁决。因此主要用于格式机制和接口可行性，源准确率仅作描述，不是未见测试或临床有效性证明。旧benchmark均已暴露，也不能在将来被称为新测试。

| 失败/未知工具 | 立即停止，不进入后续推理 | 相同 |

F1修复提示固定为：

```text
Your previous message was not a single valid JSON object. Reformat your own previous answer or tool plan into exactly one JSON object using the existing schema. Do not add analysis or a fenced block. Do not introduce a new clinical conclusion.
```

这是一次新的生成调用，由模型重新输出；不在客户端抽取原回复答案。修复轮可返回原schema的答案或工具计划，工具上限始终4；达到主6或工具4时继续遵守原最终回答约束。每条原始失败、修复提示、回复及状态都保留。

## 风险与控制

- 格式失败稀少：12例只是可行性，不为了制造阳性而挑目标错题或删失败样本。
- 源任务暴露与语境不足：不作外部或临床泛化声明，必要图像/语境不能为获得答案而猜造。
- 额外采样：两臂最大预算相同，实际发送可能不同；公开差值，不能声称已排除这一路径。
- 工具加载不稳定：源健康检查成功不等于永远健康；后续失败仍停，不将观察当阴性。
- 客户端参考泄漏：生成输入和参考分别存储，实际请求核对作为首次付费前的必要集成门槛。
