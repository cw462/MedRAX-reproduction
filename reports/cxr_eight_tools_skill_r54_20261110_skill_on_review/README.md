# R54 带 Skill 组运行前审阅

状态：待用户确认修改。这里记录已归档的 R54 基线方案。带 Skill 组尚未启动，技能库计划从空开始。

## Skill 怎么写

1. **选轨迹。** 前 10、20、30 题后各有一次学习，此后每 30 题学习一次。每窗最多保留 20 条可用于写卡的轨迹，优先覆盖不同图像和事件。错误作答和有工具支撑的短成功轨迹都可进入。技术失败、重复无进展，以及缺乏可观察操作的直接答对会被过滤。实际激活过 Skill 的轨迹也可进入归因分析。
2. **Analysis。** Qwen 根据已完成轨迹、原图、真实工具证据和已释放反馈，分别判断旧 Skill 是否被采用，以及有没有新的可复用操作。输出 `CREATE`、`PATCH` 或带具体理由的 `NONE`。证据需指向实际执行步骤。未执行的改法只进入假设记录。
3. **Mutation。** 只为已观察到的操作起草卡片。卡片有九个字段：`name`、`description`、`applicable_conditions`、`branch`、`tool_name`、`task_category`、`required_tools`、`risk_level`、`core_action`。适用条件要写明题型、目标对象、触发证据、排除条件及工具能力，操作正文要写明停止和未知情况的处理。普通 `PATCH` 一次改一个允许的字段，目标须来自当前窗口的读取快照。
4. **Review。** 对照原图、实际步骤和同范围相似卡检查候选。拒绝后允许一次定向修订，并再次审核。相似新卡可重定向为对已有卡的 `PATCH`，同样需要审核。通过的卡片从下一窗口开始可用。没有建卡数量下限。
5. **归因与治理。** 采用标签须绑定实际激活的卡片和可观察步骤。归因用于更新效用，每跨 60 道已处理题触发治理，包含合并、成熟、弃用和容量管理。答对标签和采用归因分别记录。

## 答题时怎么用

从同范围、同工具兼容的有效卡片中按继承的相似度、效用和时效规则排序，取前 15 条供模型做适用性预筛，最多保留 4 条候选。每个答题步骤根据当前题和真实观察决定是否激活，最多激活 1 条，每题最多 2 条不同的 Skill。允许全程零激活。依赖工具分歧的卡片须等同一发现确实出现冲突后才可激活。

带 Skill 组拟运行 CheXBench 618、SLAKE 114、VQA-RAD 116，共 848 题。每个数据集独立初始化 Skill、缓存和同图记忆。两组使用原 R54 八工具，均在本题预测保存后释放本题参考答案，后续答题只可见此前已释放的同图反馈。基线的主模型和 META 均为 Qwen3.7-plus，temperature 0.2、top-p 0.95、max tokens 2048、thinking 关闭。Embedding 使用 text-embedding-v4。

## 请重点审阅

- **适用范围。** 当前预筛和激活都检查题型与对象。请确认提示词是否要进一步写明二选一定位题与是非题的分界，以及工具只返回 Yes 或 No 时的处理。
- **写卡证据。** 当前 Review 要区分操作确实执行过与操作确实得到结果支持。请确认 CREATE、PATCH 的证据门槛，以及审核允许的一次修订是否保留。
- **失败处理。** 当前代码对不合法的 Analysis、Mutation 或卡片结构直接报错。已知工具失败按 R54 原协议记录并交付失败观察，未知调用保持原状态。两者是不同的处理路径。
