## 实际实验机制

固定既有618题顺序，以完整原图序列的解码RGB及尺寸精确分组：488组，130题有此前同图题，其中C41分支62题、M分支68题。首次／单例488题严格复用M43答案、理由和状态，0新调用；后续130题注入已处理同图问题、选项、模型答案／理由／状态及健康工具文本后重新执行原分支。全部130题实际有记忆，最多5条前序记录；协议上限为最近8条、记忆正文12000字符、单工具4000字符。5个图组跨原子集，共10题，故此为允许跨子集同图上下文的顺序扩展。

记忆没有参考答案、正确性反馈、未来题、其他病例或虚构病史，也没有付费总结；前序错误保留。旧工具派生图归档但不作为记忆重新附图，当前原图和当前工具新派生图另行发送。旧基线6条失败工具项不入记忆，基线答案未改。C41沿原6主／4工具预算，M沿原4主／2工具预算，原R43允许的定稿包含在总4主内；未新增D-Q或无记忆整臂。

主模型 `qwen3.7-plus`，temperature=0.2、top_p=0.95、max_tokens=2048、thinking=false，工具模型及版本沿用原记录。新工具worker绑定GPU1；其他聊天的CT/GPU0任务未由本聊天改动。新文件名保留用户包的 `r44` 后缀，本轮身份及run为R45。[原方案与修订记录](PLAN.md)、[冻结协议与顺序](PROTOCOL.json)、[代码／来源复核](CODE_SOURCE_REVIEW.md)均保留。

## 完成方式与实际故障

原主进程在 `chexbench_slake_0046` 的classifier调用发生 `SIGSEGV / backend_exit_-11` 后退出1，根因未知。该题仅2主／2工具；健康expert证据保留，失败classifier未送入后续推理，未重试、未补旧答案。独立审阅后登记 `answer/reason=null`、`missing_tool_unhealthy_stop`，冻结runner、记忆规则及配置不改。

恢复controller接续一次冻结runner。最终618预测、618记忆上下文、203发送／回复／凭证全部闭合；原child在最终审计遇到已保留的坏工具记录而以预期错误退出1。独立finalizer仅在该唯一已登记技术缺失、无额外失败题调用、预算及全量凭证核验成立后写有效完成退出0，controller实际退出0。**原退出1和child退出1保留；这是经限定恢复协议的有效完成，不是原runner全健康退出0。** 早期协议中的原始退出0门槛由已记录的有效完成门槛取代，详见[恢复设计](002-recovery-review.response.md)、[实际实现复核](003-recovery-implementation.response.md)、[完成凭证](evidence/complete_M43-IM.json)和[复现步骤](REPRODUCTION.md)。

发布检查还发现 `chexbench_openi_0045` 第2／3次已归档请求中的一个PNG字节流损坏：与规范原图同长，仅1字节不同，Pillow不能解码。第1次请求的原图有效；第3次另有有效派生叠图。原始字节单独保存，未修补或重新发送。API返回了回复，该题新旧均正确；无法确认服务端如何处理此图，也不能据此认定视觉成功。它是额外的输入完整性局限，不能宣称全部实际输入图均有效。见[输入异常证据](ERROR_ANALYSIS.md#已归档请求图像异常)。
