# R49: one registered production-tool retry

Status: **prepared, not executed**. This is an explicit operational amendment to the original stop-on-tool-error protocol. It preserves the R49 method and frozen source/configuration files while declaring one recovery attempt and a narrowly registered cache-resolution wrapper. An actual new DeepSeek operational review and a truthful existing-authorization scope record are required before launch. No new user approval is claimed.

## Evidence and limits

Production stopped at ordinal 41, `chexbench_rad_restruct_0163`: its CheXagent tool failed with an invalid CUDA kernel-image error. Forty completed predictions, prediction events, released feedback and their existing window state remain immutable. q41 has one closed paid planning request and a saved context, but no prediction or current-label feedback. All 94 Agent, 13 META and two embedding requests are closed.

One separately recorded diagnostic invocation subsequently completed in 10.615350947948173 seconds with healthy output, original image/question/revisions/BF16/512 and diagnostic-only synchronous/debug flags. It made no model API call. This establishes one successful diagnostic process, not a fixed root cause. Its medical output is never used in production inference, memory, Skill learning or scoring.

## Precisely bounded amendment

1. Refuse if any production process is active, the 40-question committed prefix or q41 boundary changed, a request is unknown/unclosed, the original error is a different failure, or a `cuda_1` production attempt was already claimed. Preserve all prior PID/log/start/exit records and raw exit 1 history.
2. Run **exactly one fresh production tool request**, zero extra Agent/META/embedding/API requests for this step. Use the existing `Tools.observe`, worker, interpreter, original q41 image and exact tool arguments, revisions, BF16, 512-token setting, timeout and GPU1. The production retry has **no** `CUDA_LAUNCH_BLOCKING` or `TORCH_SHOW_CPP_STACKTRACES` flags. Wait for GPU1 to be free and at least 3 GiB disk; do not modify other jobs.
3. Write its actual starter/result/artifacts in `generation/chexbench/services/tool_cache/<original-key>_cuda_1`. The original failed cache, starter, result and every original path remain intact. A started retry without a closed result is never reissued. If the new result is failed or unknown, stop immediately without changing the active selection or launching the main stream. No automatic second retry or technical-null answer exists.
4. Only after the actual production result passes the unchanged full health predicate, copy the original failed q41 logical selection verbatim to `ROOT/recovery/cuda_1/original_selection.json` and the self-contained `generation/chexbench/failure_events/cuda_1_original_selection.json`. Atomically replace only active q41 logical selection 1 with the real healthy retry, `cache_hit=false`, the new cache key and explicit `cuda_recovery` provenance. No prediction, feedback, context, Skill or manifest is rewritten.
5. Publish exactly one immutable registration, `generation/chexbench/failure_events/cuda_1_registration.json`, duplicated in `ROOT/recovery/cuda_1/registration.json`. It binds q41/ordinal 1, backend/revision, canonical original path, actual arguments, original identity/key/selection, actual healthy retry/key/selection, the preserved archive, closed-attempt facts and diagnostic metadata. Its schema is `r49_registered_cuda_retry_v1`.
6. A private runtime wrapper around `Tools.call` may reuse this registered healthy cache only for the same backend, revision, canonical original-image path and complete arguments within the CheXbench service directory. It writes a new immutable logical selection with the healthy retry cache key and `cache_hit=true`. All unrelated calls delegate to frozen `Tools.call`; existing selections are not silently replaced. This cache-resolution behavior is a declared operational change, not a claim that the executor is wholly unchanged.
7. Resume the same frozen R49 runner and output directory. It reuses the existing closed q41 planning response without reissuing that request, then follows the original inference loop. q41's truth remains unavailable until its prediction and prediction event are saved. A new one-use controller resumes CheXbench, then SLAKE, then VQA, preserving separate cold memories/libraries. Any further failure stops the queue again.

## Postprocessing and physical-attempt accounting

The original scorer rejects an unreferenced cache starter, so retaining the failed cache requires a narrowly reviewed historical-attempt exception. The amended postprocessor must accept only this one registered, closed, genuinely failed old cache paired with its archived original selection and actual healthy production retry. Active failed tools and all unknown, unregistered or extra orphan attempts continue to fail. The explicit-answer adapter, reference-free extraction phase and all scoring formulas are unchanged.

Report logical selections and physical attempts separately. The active fresh-selection count already includes the healthy production retry; add the preserved original failed attempt once, including its elapsed/GPU time. Do not count the retry twice. Report the separate one-invocation diagnostic and 10.615350947948173 seconds separately from production totals. Main-model costs include the original closed q41 plan exactly once. The registration and both cache attempts must be exported and publicly reproducible.

## Execution records and completion

The private helper is `local_assets/recover_cxr_online_skill_r49_cuda.py` (`stage`, `launch`, read-only `status`). Launch requires actual `CUDA_PRODUCTION_RECOVERY_REVIEW_READY.json` and `CUDA_PRODUCTION_RECOVERY_SCOPE.json` in `local_assets/online_skill_r49_preparation`. These record the user's existing R49 authorization and the exact one-case amendment; they do not invent a new explicit user authorization.

Recovery logs, PIDs and exits use `ROOT/recovery/cuda_1` and unique `jobs/<dataset>.cuda_1.log` names. Staging validates the existing healthy, single-invocation, zero-API diagnostic and raw exit 0, then copies its existing `status.json` and `exitcode` into `ROOT/recovery/cuda_1/diagnostic_evidence/` for publication; no diagnostic is rerun. Current pointers and current generation exits are updated only from actual new process/return records. Earlier raw exit 1 attempts remain archived and must be disclosed; no statement that all attempts exited 0 is valid. Full scoring remains unavailable until every dataset has complete artifacts and actual current raw runner exit 0. This work neither resumes nor changes R48 and adds no file/pixel/hash validation gate.
