# MAIRA EOS-policy amendment after 168 committed questions

Prepared only. No stage, launch, GPU/tool call, or API request has been made by this implementation. The new `phrase_guard_1` scope and actual new DeepSeek operational review are required before execution. This is a declared method amendment under the user's R49 repair instruction, rather than an unchanged-settings recovery or an official MAIRA fix.

The original [Microsoft MAIRA-2 phrase-grounding example](https://huggingface.co/microsoft/maira-2#use-case-3-phrase-grounding) uses model generation followed by decoding and the original converter. This custom amendment uses the [Transformers 4.51.3 LogitsProcessor interface](https://huggingface.co/docs/transformers/v4.51.3/en/internal/generation_utils#transformers.LogitsProcessor); it is not an upstream MAIRA repair or a clinical validation.

The isolated diagnostic reproduced `AssertionError` at the original processor's missing-end-delimiter assertion. Its 13 generated tokens ended in EOS 2 without closing-token 32001. The installed tokenizer treats both object delimiters as ordinary added tokens, so `skip_special_tokens=True` did not remove the closing delimiter. The 300-token limit was not reached. The observation establishes this format failure; it does not establish a clinical negative or resolve every possible model failure.

For all new physical MAIRA calls after activation, a logits processor examines only the generated suffix after the original prompt length. It masks only EOS 2 while an object or box delimiter remains unmatched. Other logits remain unchanged. It never inserts a delimiter or a box, deletes text, changes a clinical prompt, relaxes the original parser, or converts an error to `completed_no_finding`. The original model, original image and arguments, 8-bit/float16 factory, sampling/beam settings, decoding, `use_cache=True`, and `max_new_tokens=300` remain as before. `generation_policy_changed=true` and `same_generation_settings=false` are mandatory: EOS masking can change subsequent words, findings, coordinates, output length, and time. Clinical correctness remains unverified.

The guard verifies actual tag IDs 32000/32001/32202/32203 and EOS 2, requires no forced-EOS configuration, and stops if EOS masking would leave no finite alternative token. It neither guarantees complete grammar nor overrides the length limit. A malformed, unclosed-at-limit, failed, unknown, or incompletely observed result still stops under the original health/parser rules. There is no automatic model retry.

Each new guarded physical call additionally needs exactly one captured generation ending with actual EOS 2. Even if the original parser accepts a structure at the length limit, absent EOS or incomplete policy evidence is a technical stop before further Agent inference. The original tool envelope and raw/capture files remain saved. Runtime checks and public proof checks use this same declared gate; it is not retroactively applied to legacy healthy caches and never supplies an answer.

The activation boundary is 168 committed CheXbench questions and five completed Skill windows. Those predictions, contexts, feedback, requests, and repositories are preserved. Each dataset receives a separate `failure_events/phrase_guard_1_amendment.json` (`r49_phrase_guard_amendment_v1`), recording the original cache/selection boundary and the policy. Existing selections and healthy caches retain their original output and policy. New selections identify `legacy_healthy_cache`, `guarded_cache`, or `guarded_new`; no old cache is evicted or rewritten. This mixed-policy run must disclose its activation boundary and cannot isolate Skill learning's causal effect.

The known failed question `chexbench_slake_0053`, ordinal 169/tool ordinal 1, is eligible for exactly one new actual guarded production invocation. It reuses the original closed Agent plan, image, arguments, backend/revision, and GPU1 factory. Its diagnostic output is never reused. The old failed cache remains at its original key. The original failed selection is copied verbatim to global and GEN archives. Only an actual healthy guarded result with complete observed policy evidence permits the new `failure_events/phrase_guard_1_registration.json` (`r49_registered_phrase_guard_retry_v1`) and atomic replacement of this one active selection. A new failure preserves both attempts and stops without replacement, null completion, or another retry.

Cache naming follows the frozen `Tools.call` identity/key algorithm, including its existing image fingerprint for naming; it is not a newly introduced integrity check or image audit. The explicit suffix `_phrase_guard_1` separates guarded generation from the old namespace. Existing keys are retained. A previously failed/unknown cache other than the one registered recovery remains a stop condition. Identical healthy guarded results may be reused through the same original identity; unrelated cases or arguments are not substituted.

The private helper is `local_assets/recover_cxr_online_skill_r49_phrase_guard.py`. It stages only a new recovery controller, wrapper, worker, and pure guard module under `recovery/phrase_guard_1`, leaving the eight frozen R49 files untouched. The new wrapper delegates to the existing `embedding_arrearage_1/resume_runner.py --dataset ...` chain, retaining the earlier embedding, field, META, and CUDA amendments. The controller runs CheXbench, SLAKE, then VQA-RAD serially. Current raw exit-1 records, PIDs, logs, and queue state are archived before new current pointers. Only actual new raw successful runner/controller exits can support final completion; previous failures are never relabeled as successful.

Every fresh guarded worker preserves complete raw token IDs, decode and conversion input, exception records, original tool raw result, actual backend events, factory/GPU1/device/precision/revision metadata, EOS-masking steps/depths, final generated token IDs, stdout/stderr, and timing. The original 22.626826583-second failed selection and separate 23.471671100938693-second failed diagnostic remain distinct physical costs. The new production invocation is separately charged and timed. No additional Agent, META, or embedding request is added solely for this repair; remaining normal R49 inference continues within its existing authorization.

Launch and each new physical tool require GPU1 usage below 500 MiB and at least 3 GiB free disk, without modifying other jobs. Started-without-result is unknown and never retried. Unknown paid sends, failed tools, or a new exception stop the queue. The final state is `all_three_datasets_exited_zero_after_phrase_guard_recovery`, only after all three original runners and the new controller actually exit zero and their complete records exist. Scoring remains deferred until full generation; this amendment was not selected using target labels, scores, or clinical Skill contents.
