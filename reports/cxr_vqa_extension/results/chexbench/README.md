# CheXbench：第一阶段六组完整结果（2026-11-07）

六组均已保存 618/618，完成凭证齐全，进程退出码均为 0。六组全部来自本次扩展运行，无已发布对照复用。仅在 O 最后完成后读取独立参考答案进行六组隔离评分。

主指标为 Rad-ReStruct（115 题）、SLAKE（123 题）、OpenI（380 题）三个子集准确率的等权宏平均；618 题微平均为次指标。所有缺失均计入完整分母。

**主要发现：M 的收益集中于 OpenI，不能概括为三个子集均稳定改善。** M 相对 D 净增 42 题，微平均提升 6.80 个百分点，但主指标宏平均只提升 2.67 个百分点，其 95% 区间 [-0.19, 5.60] 跨零。M-R 的宏平均 75.39% 高于 M 的 74.36%；M 与 M-R 的宏平均差值为 -1.02 个百分点，区间 [-3.64, 1.55] 跨零。

**O 有很大的格式效应。** 严格口径 O 只有 47/618 正确、555 条缺失。统一去除一层包住完整回复的 Markdown JSON 围栏，再调用原解析器后，O 恢复 320 条可解析记录，得到 301/618 正确、235 条缺失，敏感性宏平均 55.21%、微平均 48.71%。这一检查对六组使用同一规则；原始预测与冻结严格主结果均保留，不重发请求，不依据参考答案修改输出。严格 O 分差不能全部解释为影像推理能力差距。

## 运行恢复与解释边界

运行过程中曾因共享账本 JSON 损坏停等，曾触及旧金额上限，亦发现工具缺项和 GPU 显存不足。恢复记录见本扩展总报告及仓库提交历史。用户先撤销金额上限，随后要求完全移除共享账本执行依赖；后续调用通过各请求发送标记、原始回复和用量记录恢复。历史账本、已收到回复、已有预测和失败工具观察均保留，未知已发请求没有重发。专家工具后来由被其他任务占用的 GPU 1 路由至 GPU 0。

技术失败、无效输出和合法错误答案分开呈现。O 有 192 条失败后端记录，M-R 有 85 条；这些记录以及不同阶段运行条件限制了对单一策略因素的因果归因。恢复技术流程不计作纠正合法错误答案。

CheXbench SLAKE 子集与独立 SLAKE 114 题包含 17 张像素相同图像、64 道匹配规范化题干，因此两项结果不能当作完全独立的泛化证据。
