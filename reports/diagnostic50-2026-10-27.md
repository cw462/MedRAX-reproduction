# First 50-question diagnostic comparison

Actual execution on 2026-10-27 compared two-stage direct image answering with a restricted MedRAX Agent using only the official DenseNet classifier. Both answered **24/50 questions correctly (48%)**. Relative to direct answering, the Agent changed six incorrect outcomes to correct and six correct outcomes to incorrect. This fixed development sample provides no observed net accuracy gain; it does not establish equivalence or demonstrate that the full MedRAX system or a memory intervention is ineffective.

## Results

| Observation | Direct | Classifier-only Agent |
|---|---:|---:|
| Predeclared questions | 50 | 50 |
| Correct / denominator | 24/50 | 24/50 |
| Completed with a valid final option | 50 | 49 |
| API error outcomes | 0 | 1 |
| Questions with a first-phase length stop | 16 | 22 |
| Model requests, including failed requests | 100 | 149 |
| Verified classifier returns | 0 | 49 |
| Reported input tokens | 77,727 | 180,898 |
| Reported output tokens | 19,975 | 25,603 |

One Agent request has unknown usage, so reported token totals are incomplete for that arm. A verified tool return means that its execution and output schema were checked, not that its medical assessment was correct. All 99 completed final option responses stopped normally; first-phase length stops are not counts of invalid final answers.

There were 18 questions correct in both arms and 20 not correct in either arm. The paired accuracy difference (Agent minus direct) was 0 percentage points; the paired case-cluster percentile bootstrap 95% interval was **−14 to +14 percentage points** (10,000 resamples, seed 20261027). This interval describes uncertainty conditional on this fixed diagnostic sample, not a representative population or a prespecified held-out efficacy evaluation.

The first scheduled arm started at 20:33:40 and the last finished at 21:08:30, Asia/Shanghai: **34 minutes 50 seconds**. These times exclude installation, downloads, earlier smoke experiments and later scoring. Runtime varies with API latency.

## Diagnosed problems

First-phase truncation affected either arm on 29 questions and both arms on nine. On one Agent question, a length stop and an invalid-tool-call marker were followed by a BadRequestError in the second phase. Its HTTP response body was not retained, so the exact server-side cause is unconfirmed. The outcome remains in the fixed denominator as not correct; it was not retried or discarded.

The source audit separately found that the classifier exposes operating-point-normalized image-level scores while its interface describes them as probabilities. These scores do not independently provide lesion location or laterality. This motivates a controlled wording/scope intervention; it does not establish that the wording caused any of the six regressions. See [classifier score semantics](classifier-score-semantics.md).

Before answer scoring, a [follow-up plan](diagnostic-followup-plan.md) froze the selection of the first ten questions in original input order with truncation in either arm. Both arms are rerun with the output cap increased from 512 to 1024, preserving all other declared settings and relative arm order. Protocol repair is not enabled in this comparison. This targets a mechanical failure mode and is not an independent efficacy test.

The follow-up has now completed; see its [separate results](length-cap-followup-2026-10-27.md). The full 50-question results above remain unchanged.

## Sample and reproducibility boundaries

The sample contains the first 50 distinct memory-train cases in fixed input order with a complete one-image input. Selection did not consult answers. It is not random or stratified. The 50 source image files have distinct byte hashes, which does not establish patient independence. Reference labels were read only for offline scoring; inference records contain question ID, question and image paths. This is file separation, not operating-system isolation.

The requested model was `gpt-4o-2024-11-20` through APIYi, temperature 0.2, top-p 0.95, 512 output tokens/request, at most four model and two tool calls per arm, no provider retries, 60-second request timeout and 180-second call-boundary limit. Each question/arm has fresh history. Both arms use two stages; the Agent retains the official system prompt and an adapted notebook first prompt. These choices, the proxy, limited tool set and single-image sample differ from a complete paper reproduction. The proxy's returned model ID is not independent verification of its underlying weights.
