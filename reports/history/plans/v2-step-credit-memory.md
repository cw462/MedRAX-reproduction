# MedRAX 复现与步骤信用记忆自进化：Codex 执行计划 V2

日期：2026-10-27。版本：V2。可直接作为 Codex 的任务说明。

## 0. 任务目标与交付要求

你是项目实施者。请基于官方 MedRAX 代码与原论文，首先完成可审计的胸片智能体基线，再实现跨病例成功/失败工具轨迹记忆、步骤质量评价与信用分配、动态动作选择、冲突复核和有限容量更新。优先从成功轨迹检索开始，逐步加入其他模块，不要把所有创新同时打开后才做第一次比较。

**先完成执行环境允许的全部工作。** 缺少 API、GPU、模型权重、数据权限或网络时，先完成仓库审计、接口适配、离线测试、配置、运行与续跑脚本和阻塞报告；不伪造实测、不将 mock 数据结果当论文复现。可用资源允许时继续实际运行，不要把只写计划视作完成复现。记录实际成本与预算，并支持用户设置预算和单病例调用上限；不在日志中显示密钥。

交付：
1. 真实 MedRAX Agent 评测适配器与运行手册；官方原版和改动均可追踪、创新模块可关闭。
2. 工具与代理逐步骤结构化轨迹、数据划分、运行清单和失败日志。
3. 成功/失败轨迹总结器、步骤评价模块、记忆检索、动作选择、冲突复核及容量更新的可运行实现。
4. 原论文复现、逐级消融、关键公平对照、外部数据可运行配置和逐例结果。
5. 环境、权重、许可、论文差异与仍未完成事项报告。对于未能运行的阶段，说明具体缺口及实际续跑命令。

研究假设并不保证涨点。整个系统用于研究评估，不作为独立临床诊断系统。2D 胸片实验不能直接证明 3D CT 或 COPD-PH 能力。

## 1. 方法框架：三项创新共享步骤信用评价

- **创新一：基于步骤信用的历史工具经验检索与动态动作选择。** 成功/失败轨迹经步骤评价、总结和适用性筛选后，参与候选工具、顺序及停止动作选择。
- **创新二：基于步骤信用与失败经验的工具冲突复核。** 当可比较的工具结果出现冲突、调用失败或证据不足时，结合历史复核经验动态选择重试、替换、追加异构工具或停止并报告不确定。
- **创新三：基于步骤信用和经验质量的有限容量记忆更新。** 用可验证执行信息、医学证据核验状态、适用条件和开发数据上的配对回放结果来决定入库、合并、保留与淘汰。

共享链路：原始轨迹 → 步骤评价 → 成功/失败经验总结 → 检索 → 动态动作与冲突复核 → 在允许的反馈下更新记忆池。

## 2. 不可妥协的复现边界

1. 原论文的 MedRAX 是由 GPT-4o 驱动的胸片工具 Agent。它原有同会话上下文和工具缓存；新增跨病例经验不可当作原版功能，也不能删除原有缓存以制造优势。
2. 当前官方 `quickstart.py` 直接对图片和问题调用多模态模型；它是直接问答基线，不等于 MedRAX 工具 Agent。先检查仓库 `experiments/`、`benchmark/` 和 `main.py` 是否有作者真正评测入口，若没有就为真实 `initialize_agent` 编写适配器，并用日志证明实际工具调用。
3. 论文主实验描述的工具包含 CheXagent、LLaVA-Med、MAIRA-2、ChestX-Det、TorchXRayVision、CheXpert Plus 报告生成器。仓库 README 中 MedSAM 支持尚待加入，RoentGen 可能需额外申请；不得声称全部工具已运行。记录实际工具及版本、模型许可、精度、量化和硬件。不可用时明示是受限工具版本。
4. 原文参考：ChestAgentBench 2,500 道六选一、675 个病例；论文总体 MedRAX 63.1%，GPT-4o 直接问答 56.4%。这不是验收阈值，模型快照/提示/实现/数据差异会导致不同结果。题目由 GPT-4o 生成及自动质量核验，不能声称每题医生审核。
5. CheXbench 论文使用 238 道 VQA 和 380 道图文推理，总体 68.1%；另报告 SLAKE 胸片 114 题准确率 90.35%，需要检查两者是否重叠。MIMIC 报告任务 3,858 图，论文给出 micro-F1-14 79.1%、macro-F1-14 34.2%，遵照原论文 labeler、统计和标签处理规则。无效回答论文最多重试三次，仍无效记错；应核验实际代码的计数语义并记入偏差。
6. 不要承诺论文数值可复现或某个创新必然涨点。初期实现非参数经验更新，不能把它误称模型权重训练或强意义递归自我改进。

## 3. 分阶段执行及验收

### 阶段 0：检查环境、官方实现和资产

- 检查当前目录、已有仓库、Python、CUDA/GPU/显存、磁盘、网络、API 环境变量是否存在、调用预算、数据授权。只报告密钥存在与否，不输出值。
- 获取或复用 `https://github.com/bowang-lab/MedRAX`，记录 commit、源码许可证、依赖与模型版本。隔离 Python 环境；先阅读 README 与依赖，避免污染用户环境；不使用 sudo 作为常规修复手段。
- 核查 ChestAgentBench 当前 Hugging Face 数据仓库及实际下载指令。README 与数据卡链接可能不同；以实际可访问仓库、数据文件和许可证为准。校验图像、题目、选项、标准答案、病例/图像映射、类别、数据文件版本与缺失率。
- 输出 `reports/environment.md`、`reports/tool_inventory.md`、`reports/reproduction_deviations.md`。列工具名、输入/输出、checkpoint、设备要求、权限、是否能实际执行、与论文差异。
- 允许参考的官方入门安装：`git clone https://github.com/bowang-lab/MedRAX.git`，进入仓库后 `python -m pip install -e .`；只在检查兼容及获得环境允许后执行。下载数据按官方当前 README 和数据卡核验，不把未核实的 repo id 硬编码。

验收：有可核查清单、commit 和明确阻塞；没有真实模型/工具时不声称已复现。

### 阶段 1：工具、Agent 和逐步轨迹

- 基于现有工具入口编写 benchmark→真实 Agent 适配器；一个请求得到输出、每步工具调用和失败状态。优先在能力允许时运行 classifier、VQA、report，按资源补充 grounding/segmentation。对每个工具用合规样例验证输入和返回格式。
- 做 5–10 题真实小规模冒烟：直接回答、单/多工具调用、工具失败、超时、未知工具和停止；仅功能测试可使用 mock，mock 结果必须标明，不进入实测表。
- 初始化 R0 = 原版 Agent，无跨病例记忆，保留同会话缓存、原始工具和合理的官方提示；记录所有会影响结果的修改。
- 为每个 step 保存 `state_id, step_id, tool_name, tool_version, action, sanitized_arguments, observation_summary, execution_status, elapsed_ms, cost, available_evidence, next_action`；每例另保存 case_id 的审计哈希、task_id、split、question、prediction、异常、运行预算和 run_manifest。不要保存密钥与不必要的可识别信息。
- 确保状态日志按时间排序，工具缓存命中也能追踪；记录缺图、出错、超时、无效答案及其重试。

验收：展示真实工具调用轨迹和可重放的流程证据；没有真实调用的 quickstart 结果只能标为 B0 直接模型基线。

### 阶段 2：原论文基线与病例级划分

- **原论文复现**：在论文使用的数据及规则下跑无跨病例记忆的原版，先 50–100 题分层冒烟再完整测试，列论文原值、实测值、样本覆盖、差异及原因。官方无记忆全量复现与后续自划分创新实验必须分开。
- **创新实验划分**：以患者为单位；无法获取患者 ID 时至少以 Eurorad case 为单位，所有同病例问题与图像归入同一组。建立 memory-train、validation、held-out-test 清单，病例/图像去重并保存哈希。若病例关联不可确定，报告受限，禁止自称严格患者独立。
- 标签隔离：官方 quickstart 日志可能含 correct_answer 与 explanation；适配时必须清洗并隔离这些字段，不能将整份原始日志喂给总结器。标准答案只允许开发/建库质量判定、validation 选择超参数以及独立 scorer 事后评分。测试预测过程、检索、步骤评价、总结器、更新器都不可读取测试参考答案、病人信息、未来结果或来自同病例的历史经验。验证集调好 K/权重/阈值/容量后冻结再运行一次最终测试。
- 分母为预定全部测试题，无效、超时、缺图等按预先制定规则报告，不仅统计跑通题。若某图像无法获得，单列可用覆盖率与原协议差别，不靠删除错误改善准确率。

验收：B0 直接模型、R0 真实 Agent、原文全量复现和创新数据自划分分别输出；data split 检查通过，模型/工具集、基线和偏差可审计。

### 阶段 3：成功轨迹检索，先跑第一版

1. 在 memory-train 中运行 R0 并用开发参考答案比较。选最终正确轨迹作为初始检索池，但将每个没有独立证据验证的步骤标记 `step_quality=unknown`，不能把最终正确平均分配给全部步骤。
2. 对问题中可见的任务类型、题干和允许获取的图像观察做检索；BM25 为首选，验证集比较 Top-1/3/5；先过滤任务类型、影像模态、已知视角、工具可用与版本。低相关时退回 R0。
3. 检索内容仅包含脱敏的适用条件、工具动作和风险提示，不包含历史病人的标准答案、原始报告、身份、测试标签，也不把审计哈希作检索键。确保总结器不从参考答案复制具体答案泄漏到记忆正文。
4. R1 只用成功轨迹；按相同工具、问题和预算跑无记忆、随机轨迹、等长度工具说明和 BM25，报告实际使用的 token 和费用。库建完后冻结再评估。

验收：离线测试能验证检索范围和答案隔离；资源具备时有真实新病例检索与调用轨迹，以及与 R0 的配对结果。

### 阶段 4：总结器、成功/失败经验、步骤信用

#### 4.1 总结器

输入：仅 memory-train 的原始轨迹、执行状态及授权的开发反馈。输出结构化规则：任务/影像/视角与工具版本、适用条件、正向动作、负向警示、适用限制、步骤核验等级、证据摘要、来源轨迹索引、可复核版本。校验 JSON schema、引用工具存在、个人信息和答案泄漏；不可虚构已核验的证据。LLM 总结建议由规则校验并随机人工抽查，不把总结器自信表述当真值。

#### 4.2 步骤评价与信用层级

四个维度分开存储：
- `execution`: 工具调用成功/失败/超时、参数合法性，可从日志确认；
- `task_outcome`: 整题结果与开发参考答案的比较，只存在可授权分区，不能变成对每步的自动正负标签；
- `clinical_evidence`: 某一步医学内容是否有独立标注/医生支持，取 `verified / refuted / unknown`；
- `step_credit`: 该步骤在规定情境下的配对估计，未知时为 `null`，不把 unknown 当成零或低分。

先实现可重复的规则型执行评价：工具可用、模态兼容、参数/返回格式合法、超时、重复缓存等。只对有可靠独立证据的医学步骤给予 verified 或 refuted；工具输出一致、grounding 框或 LLM 自评不等于独立医学金标准。

进阶：仅在 memory-train/validation 的少量关键状态做配对回放，固定可见上下文、工具模型与预算、后续策略及种子，对比原动作和删除/替代动作，重复运行并保留样本数和波动：

`delta_step = mean(task_score | 原动作) - mean(task_score | 替代/删除)`

同时记录调用时间和费用变化。这个值是特定环境/后续策略下的有限配对估计，不能宣称为精确因果真值；若某步骤无法被安全删除或无真实参考，则保持 unknown。不要把最终正确均分给每个步骤。若预算不足，保留规则评价并标注配对回放未运行。

#### 4.3 记忆条目示意

```json
{
  "memory_id": "m001", "source_split": "memory_train", "task": "laterality",
  "modality": "CXR", "conditions": ["comparable_laterality_disagreement"],
  "tool_versions": {"visual_qa": "recorded_version", "grounding": "recorded_version"},
  "action": "check_orientation_then_consider_grounding",
  "outcome_kind": "failure_reflection",
  "execution": "verified", "clinical_evidence": "unknown", "step_credit": null,
  "verification_note": "操作状态可确认，医学贡献待独立核验",
  "source_audit_ref": "train_case_hash", "memory_version": 1
}
```

示例为虚构结构，不是医学规则；`source_audit_ref` 只能供审计，不能进入检索键或推理上下文。把轨迹拆成多条经验时保留来源关系，以便回滚。

验收：原始成功轨迹、成功总结、成功+失败总结、加步骤评价分别可配置，unknown 不能默认为 verified；严格过滤答案/身份并保持原始日志。

### 阶段 5：候选动作选择和冲突复核

#### 5.1 记忆指导候选选择

在每一步生成最多 2–3 个候选动作，只执行一个最优候选；不是默认同时执行全部工具。先做硬约束：工具实际可用、输入参数合法、模态及输出类型匹配、剩余预算足够。对通过约束的动作按任务匹配、经核验的正向/负向经验、证据需要、成本排序；信用未知不得当已验证支持。权重与阈值在 validation 选定后冻结。排序得分不是医学正确概率。

记录全部候选、筛除理由、最终动作、引用 memory_id、是否采用、后续观测和预算。使用同长度固定工具说明、随机经验、原始成功轨迹、成功/失败经验以及同候选数的无信用评分做对照；相同模型、工具、预算和病例。若所有候选均不适用，退回原 Agent 或明确停止，不能执行不可用工具。

#### 5.2 可比较冲突与复核

定义 `conflict` 必须同一发现/解剖部位/属性、同一当前图像，且两个输出实际提供可比较的结构化值；缺失信息是 unknown 而不是冲突。检查左右方向、否定、实体映射及输出可靠性；若现有工具不能提供同一属性，停止并报告不可判断，不能靠文字猜测制造冲突。

检测到冲突或失败后，检索条件匹配的历史复核经验，按允许的额外预算选择：检查输入与格式、补充可用异构工具、合理重试、替换、停止并说明不确定性。重复相同输入/工具应通过缓存或限制避免无谓循环。grounding 结果和工具多数一致均不能替代独立标签。记录每次触发、理由、引用经验、实际工具及结果，报告错→对和对→错。

对照：原版、每题固定追加同一工具、规则触发复核、记忆辅助复核；固定平均与单例最大工具预算并记录实际花费。另可设受控故障注入（超时/空输出/输入不兼容），必须与自然病例单独报告。

验收：同一病例支持动态路径；未检测到可比输出不得伪造冲突；预算与停止机制有效；没有证据时能输出 unknown。

### 阶段 6：固定容量、去重和更新

- 在 validation 比较 K=50/100/200（初始候选，非已知最优）；固定训练病例、工具、记忆建库调用和每例推理 token 预算。比较不限容量、等容量 FIFO、随机淘汰、相似度去重及提出的质量/覆盖更新。
- 入库门控→条件兼容判断→重复与冲突检测→新增/合并→超容量选择淘汰。先匹配任务、工具版本、适用条件、失败类型，再比较语义；不能仅因文字相似合并不同条件、正负方向或相互矛盾经验。
- 在容量范围内关注任务类别和成功/失败覆盖，保护少量经核验的重要稀有失败经验。质量可参考核验等级与有限配对估计；使用次数/检索频率不等于因果有效性。
- 原始轨迹和版本变更日志不可变，删除只作用于活动检索索引；记录更新原因、旧版本、来源和时间，可回滚。避免用测试期标签改池。
- 报告准确率、记忆条目数、索引大小、注入 token、延迟、效果和不同容量的曲线；不要预设容量越大越好。

### 阶段 7：可选顺序自进化及外部验证

先完成冻结池研究。可选在线实验必须预先规定病例顺序与可获得反馈：先预测并保存→再用被允许的信号更新→处理未来病例。无标签组只接收可客观观察的工具执行状态，不得读取测试正确答案；有真实标签或医生反馈单列为有监督/专家反馈组，不得称为无标签。不同方法取得相同反馈与预算，记录时间顺序和池版本。没有可靠反馈时不运行在线医学经验更新。

严格 RSI 延伸仅作可选：系统在独立开发批次提出更新策略，验证集守门后采用或回滚，多个预先保留的批次评估持续性，最后固定策略再独立测试。仅记忆条目增删不等于已证明递归自我改进。

## 4. 实验矩阵与必要消融

| 编号 | 实验设置 | 要检验的变化 |
|---|---|---|
| B0 | 多模态 LLM 直接问答 | 无工具基线，官方 quickstart 可作为入口 |
| R0 | 原版 MedRAX，保留会话缓存，无跨病例记忆 | Agent 基线 |
| R1 | R0 + 成功原始轨迹 BM25 | 成功轨迹检索 |
| R2 | R1 + 成功轨迹结构化总结 | 总结是否有效 |
| R3 | R2 + 失败经验总结 | 失败经验增益 |
| R4 | R3 + 步骤质量评价/信用分配 | 步骤评价相对轨迹级结果的价值 |
| R5 | R4 + 信用指导候选动作选择 | 对工具选择与顺序的影响 |
| R6 | R5 + 信用/记忆辅助冲突复核 | 对冲突和失败恢复的影响 |
| R7 | R6 + 容量/冗余更新 | 受限容量下的表现和效率 |
| R8 | 可选在线更新 | 公平反馈前提下随病例变化的能力 |
| S1 | ReasoningBank 风格成功/失败经验总结与检索 | 强记忆基线；注明官方复现或受限改编 |
| S2 | ReflecTool 风格检索/候选选择 | 强工具反思基线；统一工具、模型与预算 |

重要补充对照：随机成功轨迹、同 token 固定工具说明、随机候选、无信用候选、固定额外工具、仅规则复核、无上限/同容量 FIFO/随机/相似去重。核心 2×2 对照：{无跨病例记忆、有跨病例记忆} × {无步骤评价、有步骤评价}；无记忆+步骤评价必须明确如何使用当前步骤的规则检查，不能从隐藏历史池读取信用。

R2→R3→R4 逐步变化，以拆解成功总结、失败总结和步骤信用；R4→R5→R6 分别拆解动作选择和复核；R6→R7 比较同容量策略。所有组固定基座、工具、case split、提示主体和硬预算，公开额外总结/建库费用，并另报不限制同预算的实际资源效果；不得把更多模型调用的收益全归功于记忆。任务次数与低调用组差异、只在子集执行的评价与受控故障应明确分母。

## 5. 指标、统计和人工审核

- 问答：总准确率=答对题数/预定测试题数；同时报告有效回答率、错误、缺图和超时；按论文七类和病例分层，记录同病例多题相关性。
- 工具：成功返回数/全部尝试调用数、无效工具调用、重复调用、单病例调用数/时延；执行成功不是医学正确。
- 信用：已验证步骤占比、unknown 比例、配对回放差值及不确定性；不可把检索次数当有效性证据。
- 复核：预定义冲突的触发率、可评价病例分母、错→对、对→错、无法判定和额外成本；有标注的子集中才计算医学冲突解决正确率。
- 记忆：条目数量、类别及成功/失败覆盖、命中/采纳、容量、token、入库/淘汰频率，记录关联不作因果宣称。
- 对同病例按病例或患者聚类 bootstrap，给配对准确率差值及 95% CI；较小亚组保留原始分母，不夸大结论。按需多次模型重复并记录种子、模型快照、温度。
- 专家审核可在资源具备时抽取病例，盲评证据与最终结论、侧别、否定/遗漏；明确样本规模、标注一致性和核验成本。

## 6. 其他数据集和泛化

1. ChestAgentBench：原论文基准和病例级自划分记忆研究；原始复现不等于外部泛化。
2. CheXbench / SLAKE 胸片子集：原论文 VQA/推理复现；核查题目、图像及患者重叠，不当作两个完全独立集。
3. MIMIC-CXR-VQA：跨数据集胸片问答；核查数据授权、问题自动生成和图像来源；按患者独立分组及工具预训练重叠审计。
4. MIMIC CXR 人工核验 VQA：补充医学人工评价，但与 MIMIC-CXR-VQA 同源，不能称不同独立中心。
5. VinDr-CXR：跨机构检测/定位；按原标签构造任务且经核验，沿官方划分并确认患者级信息；不是现成的工具轨迹 benchmark，也没有 RHC 肺动脉高压金标准。
6. MIMIC-CXR 报告生成：按论文原评测复现 CheXbert 标签和 micro/macro F1，注意预训练重叠。

外部冻结协议：以 ChestAgentBench memory-train 建库、validation 调参，冻结后直接在外部测试；禁用外部测试标签反馈。外部适配协议：外部独立开发病例建库/更新，冻结后在不同外部测试患者评估；不称零样本。核对跨数据集图像/患者重复及各工具预训练重叠，不能排除时写明。数据不可得时产出可运行适配配置和明确授权步骤，不能伪造外测结果。

## 7. 配置、文件、日志和验收测试

实施前检查官方仓库实际结构；以下为建议，不假定这些文件已存在：

```text
configs/                  # 数据、模型、工具、预算及 R0–R8
adapters/                 # 数据读取与真实 Agent 适配
trace/                    # 运行事件和逐步骤日志
credit/                   # 规则评价、医学证据状态、配对回放
memory/                   # 总结、检索、门控、更新、版本
policy/                   # 候选动作、冲突/复核、停止
experiments/              # 划分、运行、比较、统计
artifacts/runs/<run_id>/  # 配置、清单、逐例输出、轨迹、统计
reports/                  # 环境、复现偏差、结果、阻塞和续跑
```

配置字段至少包含 data_version/split_hash、LLM model ID/snapshot/temperature、tool versions、memory snapshot/capacity、summarizer version、credit mode、retrieval K/threshold、candidate count、max tool calls、timeout、max token、seed、feedback protocol。最终保存实际运行命令和每步失败/重试；按 problem_id 断点恢复，保证不会把中途失败记成成功。

必要的自动检查：
1. 同患者或病例无跨组；无法判断时明确限制；图像哈希去重和划分锁定。
2. 测试参考答案无法被 agent、retriever、summarizer、credit、updater 读取；memory 构建字段中无答案与身份。
3. unknown 信用是 null，不能被自动当 0 或 verified；工具执行成功不得被当医学正确。
4. 固定池推理前后哈希一致；容量上限、版本变更和回滚有效；正负经验或不同条件不会仅因相似被错误合并。
5. 候选动作只有真实可用工具、格式合法；冲突匹配同实体同属性，缺失证据为 unknown；受控失败不会引发无限重试。
6. 指标使用预定分母；断点恢复不重复计数；基线和实验记录同一模型/工具及预算；mock 与真实运行隔离。

每个阶段都写具体复现命令，命令以实际代码为准，不在交付文件中把预想命令伪装为已实现入口。若安装、下载或推理失败，提供退出码、最小错误上下文、环境与重新执行位置。
