## 3. 冻结数据与三种评估协议

### A. 原论文基线复现

在项目许可和预算条件下，保留作者给出的题目/图像及工具、尽量对齐提示、多图输入、每病例对话上下文、工具、答案解析和重试。输出 full paper-benchmark 结果，并列与原文模型快照、第三方 provider、图像缺失、多图处理、上下文、工具数量及依赖的差异。论文 63.1% 是历史参考，不是本系统必须达到的门槛。若只能在受限工具运行，清楚命名 `paper_benchmark_restricted`，不能称完全原版。

### B. 记忆方法独立评价（主要创新实验）

复用已有冻结的 `data_tools/prepare_splits.py` manifest 与 seed；目前代码采用 case 级 60%/20%/20%，即 `memory_train`、`validation`、`heldout_test`。609 case 的理想数约365/121/123，实际数量、每组问题数和图片可用性必须以冻结 manifest 为准，不按估算当事实。已有 50 题全属 memory_train，只用于开发或建库，不得重分为 test。

- 同一 case 的全部题、全部图像不跨组；查完全相同图像字节和可合理核查的近重复、来源 ID，并保留映射。患者ID不能核验时说明是病例级，而非患者级。
- validation 用于模型协议、阈值/Top-K、summarizer、工具选择与容量设置；最终方案和 pool snapshot 固定后，heldout_test 只评估、不能用于修改系统。完整 heldout 的所有预定义可评估问题应按固定分母对同一批病例运行各比较组；缺图、超时、无效单列，遵照预注册判分规则，不只对成功题算准确率。
- 原论文全量 R0 与真实 memory 实验 heldout 必须分开；原论文全量已经包含 heldout，运行它的结果只能由隔离评测器封存，不能在做完后按题/病例分析用于选择后续改进。若之前已查看某些测试结果，应如实记录并另准备未用于决策的新评估集，不假装原 heldout 未见。
- 原数据 `correct_answer`、`explanation` 不得进入 inference、memory、query、summarizer 或 test 阶段优化。使用推理/评分独立进程或权限隔离；仅分文件不是强隔离。训练开发结果只能作为建池的 outcome 标签或合法验证，绝不传给测试 Agent。

### P1. 协议稳定与真实多工具 Agent

**P1.1 输出/工具语义控制。** 在 validation 的预先选定开发病例（目标至少30题，若不足如实使用全部）比较 512/1024 上限与有效结束状态；设重复512对照和重复运行，先不引入记忆。病例和顺序事先按 seed 确定，不按答对与否挑选。此前10题可作排查，不重复计为独立样本。若预算或服务波动无法重复，则明确观察性结论。

**P1.2 工具说明单因素。** 分类器原始说明与“操作点对齐分数、不代表概率、不提供侧别/定位”的修正说明，在同工具、提示主体、案例与调用约束下单独对照；不同时混入记忆、EOS或beam变化。效果为开发结果，在 validation 冻结是否启用。保持一条原始论文工具配置基线，工程修正版本另命名。

**P1.3 多工具真实 smoke。** 先将已真实跑通的 classifier + report 两类工具接入同一真实 Agent，对5–10个 memory_train 开发病例核验实际可选、实际调用、输出接收、失败回退、停止与追踪；视实际接口再加 ChestX-Det segmentation。优先低显存工具、惰性加载/卸载和顺序推理，记录 RTX 3090 运行实际峰值，未加载不能冒充；再核实 VQA/grounding 权重许可和显存，不可用就标受限工具，不伪造。多图/多工具不得默认强制每题都调全部工具。

**P1.4 报告生成参数**：原版、EOS-only、beam-only、EOS+beam 四组选配，先按项目已有5张结果确认行为；如新增测试，只在开发集独立评估输出一致、长度、时延和可能的医学文本变化。EOS工程效率与临床质量/问答准确率分开，不把EOS修复悄悄计入原版或记忆增益。

### P3. 第一优先：只检索成功轨迹（R1）

- 扩展 `memory_core` 或新增适配层，把**真实的**经过脱敏审计的轨迹转成结构化经验，标记 source split、tool/version、task、conditions、action、风险和 outcome。现有固定词表会限制真实经验覆盖，扩展要保持强schema、严格模板与证据来源；不可把手工预设模板当真实提炼结果。
- 检索仅依据推理可见任务、问题、图像可观测信息及工具可用性，先兼容性过滤再 BM25；Top-K候选1/3/5和阈值只用validation选，低匹配回退R0。历史标准答案、解释、患者识别信息不得进入检索正文；同病例全部问题排除；memory snapshot冻结并校验hash。
- 先在 validation 预先确定至多 80 个不同病例、每例至少一题（如条件不足列实际N），对 R0、R1 做配对比较；加随机成功轨迹和相同token的固定工具说明对照。使用 memory_train 真实成功轨迹，不用 validation 答案建库。该轮是开发，不能称最终泛化结果。

验收：记忆确实被检索和注入、记录 memory_id/是否采纳、工具动作变化和费用；无可用成功经验时如实报告不运行，不可注入测试答案。

### P4. 总结器、成功/失败经验与步骤信用（R2–R4）

- 实现轨迹总结器：输出适用条件、正向工具动作、失败与风险、适用限制、可见证据、source trace/version、核验状态。输出 schema 检查、禁止原始答案与病人信息，自评不作为医疗真值。分别比较成功原始轨迹、成功总结、成功+失败总结。
- 四种标签分开：execution（工具可用/参数/超时/返回，日志可核实）；task_outcome（仅建库/开发可见的整题对错）；clinical_evidence（独立证据支持/反驳/unknown）；step_credit（条件性配对估计，unknown=null）。不能把最终正确均分到每步，也不能把工具执行成功写为医学判断正确。
- 首先规则评价可确认的执行质量。进阶在 memory_train 或 validation 选预先确定的**至多30个可重放关键状态**，对原工具动作与删除/替代动作在同可见状态、模型/工具、后续策略、预算和相近随机设置下重复配对；记录得分差、样本量、时间、费用及不确定。无法可靠观察则保持 null；配对差是情境依赖估计，不宣称精确因果真值。
- 在 validation 比较无步骤评价、执行规则评价、可用配对信用；模型候选数和预算保持一致，记录 step_credit 可用率及unknown率。

### P5. 动态动作选择、冲突复核、记忆容量（R5–R7）

- 动作选择：在每一步构造最多2–3个候选动作，按任务、模态、工具可用和输出能力硬过滤，再用经核验经验、信用与成本排序；只执行第1个，然后重新观察。低相关或全部不可用回退原Agent或停止。排序分数不是医疗概率。对照随机/无信用、同候选数/同token和工具预算。
- 冲突复核：只将同图、同病灶和同属性可比较的输出判为冲突；分类分数不含侧别，不能用它制造左右冲突。根据历史经验选检查输入/方向、重新调用、替代可用工具、追加互补工具或停止并表明不确定。定位框和工具一致不等于金标准。对照固定额外工具、规则复核与记忆辅助复核；记录错→对/对→错、可评价分母、时延和费用。人为注入失败应单独报告。
- 容量：validation 比较不限容量以及 K=50/100/200 下 FIFO/随机/纯相似去重/步骤信用+质量+覆盖策略。实际经验不足时记录条目数，无法测试某K则标不可评价；不能重复造经验填满。先匹配任务、条件、版本、正负与错误类型，再计算相似；稀有已核验失败保留配额；原始轨迹不可变、版本可回滚。最终在 validation 选一个方案、冻结。
- 做逐级消融以及单项对照；如果某个模块还没实现，不得把整条链标为已完成。

- 必须报告各组全量预定测试问题数、已运行数、缺图/失败、有效回答率、正确数/总数、accuracy及患者/病例聚类配对95%CI；每题题型与每病例多题聚类、错→对/对→错，单/多图覆盖，实际调用次数、费用、token、耗时；若运行中被预算中止，报告**截至当前完成的配对样本和剩余任务**，不得把部分结果标成完整结果，也不得依据已观察的test结果再选超参数。
- 论文全量 baseline 与 heldout 创新比较独立展示；如果运行全2500题，区分全量原版、已获图像覆盖及不可用项，并标明该全量baseline与heldout有重叠不能视作外部测试。
- 比较 ReasoningBank/ReflecTool 风格强基线需相同工具/模型/预算；如只做轻量改编，明确写 `inspired-by adaptation` 而非声称官方完整复现。

### P7. 外部数据与可选在线更新

按第3节取得相应授权后，使用冻结池进行外部测试，先检查题型/格式/工具适配、预训练重叠和test参考隔离。外部开发集适配与冻结直接迁移分表。为进度和成本设预定样本与分母，并在完成条件允许时覆盖完整外部测试。

在线模拟另设协议：病例按先验顺序先预测、持久记录，然后只用预先允许的反馈更新。无标签组可用工具执行状态，不得读取测试真值或将自评当医学事实；提供医生或真值反馈的组命名监督反馈，与无标签组分开，公平匹配反馈和预算。重复不同预定义顺序，比较冻结池。仅记忆变化不自动等于强递归自我改进；只有独立验证、策略选择/回滚和多个批次改善的证据才可进一步讨论。

## 5. 主实验表与核对

| 编号 | 版本 | 核心差异 |
|---|---|---|
| B0 | 相同VLM直接回答 | 无工具 |
| R0-1 | 真实单分类器 Agent | 与已有50题结果对齐，非完整Agent |
| R0 | 冻结多工具 Agent，无跨病例记忆 | 记忆方法主基线 |
| R1 | R0 + 成功轨迹BM25 | 先证实检索 |
| R2 | R1 + 成功轨迹总结 | 总结的作用 |
| R3 | R2 + 失败经验 | 成败经验贡献 |
| R4 | R3 + 步骤执行质量/可验证信用 | 信用分配的作用 |
| R5 | R4 + 候选动作选择 | 下一步工具与顺序 |
| R6 | R5 + 冲突复核/替换/停止 | 冲突处理 |
| R7 | R6 + 固定容量和质量覆盖更新 | 可持续记忆管理 |

辅助对照：随机轨迹、同 token 工具说明、随机/无信用候选、固定额外工具、无条件或规则触发复核、无上限与等容量FIFO/随机/相似度去重。总训练建库调用与生成token费用不只算推理开销。记忆×步骤评价可做2×2：无记忆/有记忆各有无规则评价；无记忆组不得隐式加载跨病例信用。

若要声称创新，需比较已有相关经验与验证方法，重点验证医疗工具选择/冲突适用条件、真实步骤质量和容量约束下的增量；不预先承诺涨点。
