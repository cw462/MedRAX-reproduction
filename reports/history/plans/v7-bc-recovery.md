# MedRAX V7：同时保留 B/C 纠错收益、减少有害改答的逐题分析与实验计划

日期：2026-10-29。适用：Codex / DeepSeek Harness。
项目：https://github.com/cw462/MedRAX-reproduction 。读取版本：`44177fa92513fef32479f6e7ea7cd50cb1f236b5`。

## 1. 先给结论

本轮不能只研究为什么 B 退步，也不能因 C 总分较低就丢弃 C。B/C 各自纠正 A 的 8 题，其中共同纠正 5 题，各自独有 3 题；两者都存在可保留的互补信息。

新的主要目标是：**保留当前病例的初步答案与证据，让记忆提出候选修改；针对修改涉及的具体属性补证，仅在当前证据支持时接受修改。** 这是减少有害改答的设计，不是零损害保证。完全禁止改答可以零修改损害，但也会丢掉全部纠错收益，不能作为成功方法。

本文件优先于 V5 的 B1/B2/B3 排序主线。已完成的检索实验保留；全图历史图像重排后移。不要重跑哈希、图片字节、账本或环境审计来代替方法验证。

|---|---:|---:|---:|---:|---:|

共有 **28 题三组正确性不同**，是第一批完整复盘对象；其中 11 题是至少一种记忆修复 A 的错误，17 题是至少一种记忆损害 A 的正确答案。不能只看 17 道损害题而丢掉有效经验。

特别地，B/C 共同损害的 6 题中，两者选择了同一个错误选项。直接对 A/B/C 多数投票、无多数时沿用 A，离线结果是 **38/60**：只保留共同纠正的 5 题，却接受共同损害的 6 题。该结果由现有预测计算，没有新增模型调用；它说明“一致就改”不适合作为接受规则。

## 4. 哪些是已知事实，哪些还需要原始日志

本报告已经连接公开预测表与官方 metadata，核对题干、所有选项、标准答案、解释、图片引用及 A/B/C 答案。因此下面能具体说明“改错了哪个属性”。这里的正确性以 benchmark 标准为准，不代表对原始影像进行了独立临床判读。

**公开仓库没有 S2 的逐题实际注入全文、完整检索列表和完整工具语义轨迹。** 因此不能断言某题是某条 Skill、某个模型输出或某次早停导致。解释按三层记录：

1. 答案层事实：A/B/C 选择与具体属性差异。
2. 代码层风险：实现确实可能引入的影响。
3. 待验证机制：必须用对应运行日志定位，不能伪装成已证实根因。

目前 C 的代码风险包括：总结只取前 6 步、每步 facts 前 280 字符；检索包括选项；有限病征词过滤不能覆盖对象/时序关系；1400 字符放不下一张卡时会截断。B/C 的训练来源也不同，不能将两组差异解释为纯粹的表示消融。上述风险需要逐题验证。

对下面附录的 28 题生成 `bc_error_forensics.jsonl`，每题包括：

```text
题干与选项的原子属性
A/B/C 实际回答与标准评分
B/C 真正渲染后注入的条目、原文与来源
首次不同的工具动作/参数/所用图片
各关键属性最早来自哪个可见观察
某个属性是否在压缩、总结或最终回答时丢失/反转
有无新工具证据支持改答
首次偏离发生在检索、工具观察、证据汇总还是选项映射
机制证据等级：confirmed / supported / unknown
```

命中 Top-3 不等于三条都渲染进入 prompt；必须以实际文本为准。若某字段未保存，记录 missing，不重构不存在的事实。

顺序：6 道共同损害 → 8 道 C 独有损害 → 3 道 B 独有损害 → 11 道纠正。最后检查 22 道共同正确与 10 道共同错误的整体模式，避免只分析变化病例产生片面结论。

从真实收益轨迹提取“什么动作解决了什么差异”；从损害轨迹提取“在什么条件下不该套用这条经验”。只有可见动作与结果支持时，才归入 Skill；不能因为该题答对就把所有步骤记为正信用。

## 7. 核心改进一：把候选答案拆成可核对的原子属性

用完整选项分析候选差异，但不把候选假设当成已见事实。每项至少保留：对象、图像/视图/时相、属性、值、否定、程度、参照对象、临床推论、证据来源。

例如 722 的 D 与 C 不只诊断名不同，而是支扩位置、实变位置、大小关系三处不同；11804 则是两个病征各自的左右分布；3436 仅差第 7 与第 8 肋间。

建立 `proposed_edit_set`：只列候选修改相对暂定答案真正改变的属性。补证围绕这些属性提出明确问题，避免再次生成宽泛报告。

首批训练 Skill 类型：

- 精细位置与参照定位：肋间、肺区、胸壁/纵隔关系。
- 双对象绑定：对象 1 与对象 2 分别定位后再比较。
- 否定与存在性：有/无结肠袋影、有/无空气支气管征、有/无钙化。
- 分病征时序：实变完全/部分消退，与网状影持续/增多分别判断。
- 临床推论一致性：题干目标、已见病史与选项因果关系是否相容。
- 缺失上下文：识别无法由现有图像/题干补齐的病史，不用记忆猜出患者事实。

这些是从错误类型提出的通用设计；不能把上述开发题的标准答案写进训练卡，也不把病理结论当作当前影像直接可见事实。

## 8. 核心改进二：先保留当前判断，记忆提出旁路建议

先由无记忆 Agent 获取当前病例证据与暂定答案，保存可见多模态 checkpoint。B/C 式经验在此后作为动作建议来源，不在最初观察前覆盖当前判断。

同一状态分别构建 B 来源和 C 来源的候选分支：

- B 来源保持原结构经验来源，依据当前差异选择适用工具经验。
- C 来源保持原语义 Skill 来源，保留适用、动作、检查、无效分支和停止字段。
- 每次最多一条适用经验。两种来源都能选择不用记忆，回到通用补证策略。
- 记忆负责“检查什么、怎样获得证据”，不提供当前患者的诊断、坐标或事实。

来源、内容、检索与渲染变化须记录。B/C 库不同，所以两分支比较代表来源策略比较，不是严格的纯表示消融。

原始轨迹保存真实图片引用与图像角色，可为后续多模态检索准备，但本阶段不加历史图片，不让视觉重排混入。

## 9. 核心改进三：按当前证据接受或拒绝改答

接受门控只输出 `accept_candidate / retain_initial`，不能自己生成第三个答案。接受必须满足：

1. 建议处理的是当前题真正需要的差异。
2. 用于支持修改的观察对应当前病例正确的图像、对象与时相。
3. 每个关键改动属性有可追溯支持，或明确纠正了先前可见证据的错误解释。
4. 修改没有附带新增的无依据断言，未把“未提及”变成“没有”，未混淆完全/部分、持续/加重。
5. 可比较冲突已得到处理；只有模型自报更自信、工具多数一致或 B/C 意见相同不够。

针对“异常→正常”的改动，逐一解释原阳性证据为何被否定；不能由报告未提及异常直接改正常。针对复合选项，不只验证其中最容易的一句话。

门控可以检查当前已有证据并发现推理/选项映射错误，不强迫所有修改再调用图片工具；真正缺视觉信息时才定向 VQA、跨视图比较或全图＋当前 ROI。ROI 必须来自当前病例有效目标框且保留方向/参照，无框不伪造。

候选流程最多一次补证、最多两次底层调用；三条实验分支使用相同动作集合、输出上限和总调用/时间预算。候选失败或缺少支持时返回本次真实获得的暂定答案，不复制历史 A 答案冒充运行结果。

**不能保证零损害**：当前工具和门控也可能误读证据。门控阈值/规则只能在训练数据上确定，开发题答案仅供离线评分。

## 10. 主实验矩阵：同时检查两种记忆来源

每道开发题共享同一个真实无记忆前缀和初步状态；保留问题、所有当前图片、可见工具输出、消息顺序与剩余预算。旧记录若不完整，实际采集一遍共享前缀，不用截断文字假装恢复原多模态状态。

| 分支 | 行为 | 回答的问题 |
|---|---|---|
| P0 | 直接输出本次暂定答案 | 共同无补证对照 |
| P1 | 无跨病例记忆，按候选差异通用补证 | 多一次定向复核自身的收益 |
| PB | B 来源建议＋同预算补证，输出候选答案 | B 经验在后置使用时的收益/损害 |
| PC | C 来源建议＋同预算补证，输出候选答案 | C 经验在后置使用时的收益/损害 |
| GB | 与 PB 共享建议、补证结果和候选答案，只增加接受门控 | 阻止 B 来源损害时保留多少纠正 |
| GC | 与 PC 共享建议、补证结果和候选答案，只增加接受门控 | 阻止 C 来源损害时保留多少纠正 |

P1/PB/PC 各覆盖同一 60 题，共 **180 个新候选分支结果**。GB/GC 不重跑工具，在相同候选上执行门控；若门控使用模型，其额外调用和时间单列。无触发题共享 P0，记录为未干预，不伪造额外调用。

第一阶段只做一轮机制验证。旧 B/C 的 8 次纠正不是新 PB/PC 必定保留的结果；先报告这些历史病例是否仍被修复，再以本次共同 P0 重新计算纠正和损害。

第一批不要直接合并 B/C 盲投票。若两来源都有可重复贡献，再用训练状态学习按缺口选择来源，或建立保留来源字段的统一动作池；作为新组单独比较。

## 11. 关键指标：不能只看总准确率

以任一候选 U（PB 或 PC）和对应门控 G 为例：

```text
纠正数 = P0 错、最终对
损害数 = P0 对、最终错（含没有有效最终输出）
净增益 = 纠正数 − 损害数
纠正保留率 = U 已纠正的题中，G 仍正确的比例
损害阻止率 = U 已损害的题中，G 保住 P0 正确答案的比例
```

分母为零时记 N/A。门控只在 P0/U 二选一，可以明确量化“保住了多少收益、挡住了多少伤害”；不能仅报告拒绝率或剩余准确率。

另报 P1/PB/PC 的动作变化、新信息覆盖、记忆采用率、每题费用、平均/中位/P90 用时。以全部 60 题为分母，T4/T5 和其他三类、单图/多图分别报告。

共享前缀的实验实付费用与每组部署时应承担的完整逻辑成本分开。所有门控和补证调用均计入部署成本，不能只算最后一次回答。

按病例计算配对区间；重复运行仍只有同一批病例。历史 A/B/C 与本次前缀不一致时分别列明，不能只挑最好的轮次。

## 12. 如何继续步骤信用与自进化

先在训练数据分别为 B/C 来源保留成功、失败、未知的动作经验；根据真实调用标记执行有效、是否对准缺口、是否增加信息。整题对错不能自动赋给每一步。

工具步骤信用使用 20 个训练状态、do/skip 两分支、各重复 3 次；同一原图、可见状态和后续回答策略，按 `checkpoint_id + action_id + repeat_id` 显式配对。信用按缺口/动作/必要条件存储，不是工具全局分数。

接受/拒绝修改的效果属于“改答决策信用”，与工具步骤信用分别记录。不要把门控收益冒称工具贡献。

训练中更新一次动作池后冻结，再跑新信用组；开发集、heldout 运行日志不写入可检索长期记忆。容量和冗余更新放在已有动作收益成立后的长期实验。

## 13. 执行要求与阶段交付

1. 先离线完成 28 题日志复盘，输出“明确机制/有支持/未知”分级，不因日志不足中止其他工作。
2. 从训练病例构建差异属性和动作卡，完成 P0/P1/PB/PC 的真实多模态续接。修复现有文本续接和信用配对的直接方法问题，不展开无关审计。
3. 冻结门控，在同一候选结果上计算 GB/GC；完整跑 60 题，不只跑已知错题。
4. 若门控在保留纠正的同时减少损害，固定该方案、对应未门控组和无记忆组，同期端到端再跑两轮。没有正向信号则报告原因，不无限调阈值。
5. 锁定方案后再安排既有独立 heldout；这 60 题继续作为开发分析。
