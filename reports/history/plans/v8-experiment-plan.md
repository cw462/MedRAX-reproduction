# MedRAX V8：静态医学知识＋动作经验＋步骤信用实验计划

版本：2026-10-30。交付对象：Codex / DeepSeek harness。仓库：<https://github.com/cw462/MedRAX-reproduction>。

## 0. 接到本文件后直接做什么

以本知识包为输入，在现有仓库建立独立实验分支，实现下面的共同控制器、K/E 接口及逐题日志，然后按阶段运行。无需重新开展图像哈希、发送字节、输出计费上限或环境审计。沿用已工作的模型和工具连接。本次不把输出设为512 tokens当作论文硬性要求；采用当前已验证的统一输出配置，所有比较组保持一致。若因结构化输出被截断必须调整，统一调整全部组并记录，不能单独照顾改进组。

先执行包内本地检索示例，再接入仓库真实多模态调用。不要把本地检索测试成功写成准确率提升；本包尚未执行新的医疗问答模型实验。

必须产出：每题共同初判、各组最终答案、纠正/损害交集、实际注入卡、所需证据、工具动作、改答理由、耗时和成本，以及可重跑配置。允许无适用记忆时零注入。

## 1. 研究目标与已知基线

核心目标是提高 **纠正数−损害数**，同时保留 B/C 已展示的互补收益。不能保证把所有原正确题都保护住；门控自身也会错误拒绝有效纠正，必须同时测量。

历史60题：A39/60；B38/60；C33/60（含1次预算失败）。B相对A纠正8题、损害9题；C相对A纠正8题、损害14题，其中13次错误回答、1次执行失败。在共同完成59题上C损害13题。B/C共同纠正5题、各独有纠正3题；共同损害6题、B独有损害3题、C独有损害8题。开发题明细位于 `evaluation/bc_case_deltas.csv` 和 `documents/Experience_Synthesis.md`。

这些60题已被反复分析，只能用于开发观察。当前C还改变了经验池构成，不能把B/C差异全部归因于“Skill表示优劣”。现有公共日志不足以证明每题具体因果链；不得把推测写成已证实的检索错误。

## 2. 三种信息分开存储

| 名称 | 内容 | 权限 |
|---|---|---|
| W：本病例工作状态 | 当前图像、题干、可见病史、对象/部位/视图/时相、工具观察、候选假设、待解决属性 | 随本题更新；观察需绑定实际证据 |
| K：静态知识库 | 指南、影像术语、正常变异/伪影、鉴别检查点、适用边界 | 本轮冻结；以来源修订更新，答对奖励不能改写医学规则 |
| E：经验Skill池 | 训练病例的成功/失败工具动作、适用条件、检查点、分支、步骤信用 | 只在训练阶段更新；开发/测试冻结 |

K说明“判断需要什么”，E建议“如何获得或复核这些证据”，W记录“本病例实际具有什么”。知识引用不是患者征象的证据。方法论文、开发题答案、官方解释、病例分析文档不得进入K/E运行索引。

每条观察采用 `(image_id, view, timepoint, entity, region, attribute, value, status, provenance)`。`status`为observed / reported / hypothesis / unresolved。左右/部位/时间缺失不得隐式补全。同一图的重复模型推断不能伪装成多个独立支持来源。

## 3. 知识内容的使用优先级

1. 属性、定位与关系：投影、PA/侧位互补、轮廓征、同一对象对应、遮挡及技术伪影。
2. 变化与多病共存：分别追踪每个征象的存在、范围、程度及时间，不把一个病征好转推广到整个病例。
3. 鉴别所需征象：外观相似时需要验证什么、哪些阴性结果不足以排除、疾病名不能替代图像证据。
4. 指南的适用范围及检查选择：人口、临床情境、已有模态和能力边界。指南更适合补齐证据要求，不适合直接决定当前选择题答案。

包内临床PDF已经下载、提取，并附来源与页码；不是穷尽全部胸部医学知识。未被现有卡覆盖时应返回空结果。CT专属细节不用于仅有胸片的形态结论；“能力边界”卡可指出缺少CT证据，但不要求调用不存在的CT工具。常规成人指南不覆盖免疫抑制/儿科时，人口条件未知则作为有限适用或拒绝，不能默认满足。

## 4. 两层检索：先找到规则，再找到动作

### 4.1 查询构造

E的初次查询与索引都使用原始题干，移除答案选项、gold、官方解释、模型生成的最终诊断。保留训练经验正文用于检索命中后的条件检查，但不能把参考答案拼进索引文本。缺失原始题干的旧条目不自动填入猜测题干。

K的查询为结构化对象：`question_stem + task + modality + observed_evidence + missing_attributes + hypotheses`。其中hypotheses单独标记为待验证，不能进入observed字段。可以从候选选项提取真正不同的属性（例如是否有某征象、哪个部位、是否完全消退），但不把选项整段复制为检索事实。为每个关键差异生成一条短查询，最多2条；不使用HyDE虚构患者报告。查询改写不得加入原题没有的阳性病史或发现。

同时保留一条严格题干查询作为消融。若使用差异属性查询，必须在所有K组一致开启，并记为显式方法变化，不能称为严格B1题干检索。

### 4.2 推荐候选检索器

第一版运行路线：**BM25＋dense → RRF →适用性重排/拒绝→来源去重→少量知识卡及原文依据**。

- BM25保护解剖部位、否定词、视图和罕见征象等精确匹配；dense补同义词/释义检索。
- 各通道取至多30候选，RRF的k先固定60。不能把BM25数值直接与余弦相似度相加。
- 包内可运行演示使用真实MiniLM ONNX编码器；它不是医学专门模型，也不是中英跨语种性能已验证模型。英文检索字段与中文阅读摘要分开。
- 正式检索消融候选：英文语料的MedCPT query/article双编码器；中英混合的BGE-M3。二者均要在训练来源的检索标注集上与BM25比较。使用其指定的query/document编码方式，不能把不同模型embedding混入同一索引。
- 包内重排是明确规则的scope/condition rerank，**不是已实现的CrossEncoder**。若训练检索集显示提升，再加医学适配CrossEncoder或支持中英的reranker；不得只因“更复杂”默认开启。

适用性检查区分两种信息：卡要求的观察尚未得到，可生成待查项；卡适用模态/人群/情境与病例明确冲突，则拒绝。不能因为当前缺失的正是目标征象，就把有用的核查卡全部过滤掉。否定证据需要解释，含某疾病词但用于排除该疾病的卡不应被当成阳性支持。

实施边界：当前59卡的多数前提仍为自然语言。包内引擎能检查显式模态/任务与结构化条件；自然语言的人群、病史、例外及语义否定仍由调用层复核，不宣称已实现完整医学适用性推理。不能将`recommendation_applicable=null`当作适用；它表示未判定。知识卡适合提出待查要求，不直接授权改答。

每次最多2–3张K卡、每来源最多2张，去掉重复定义，保留不同来源的有用互补。短卡负责匹配，回取其页内原段负责查证。保留句子与前提，不截断到只剩疾病名。长PDF不等长切碎后整页灌入提示；图注里的示例病例不可冒充当前病例。以card_id、source_id、PDF页作为引用，不依赖向量分数充当可信度。

如果所有候选都不适用、证据关系不清或低于预注册阈值，返回`inject=false`。记录候选与拒绝原因；不要为了凑TopK注入无关指南。多源互相冲突时保留版本与范围，不能简单投票。

### 4.3 训练检索标注集与消融

从独立训练病例或指南规则创建30个查询：10个精确征象、10个同义/否定/跨表达、10个不适用或应空检索；标注相关性、适用性及是否只能提出待查要求。有条件时由两名独立审核者复核；暂缺人工审核时先按来源建立临时标注并明确其局限，继续冻结方案和执行主实验，不把它表述为已通过人工医学验证。不得由60开发题答案反向生成检索测试。

在同一卡库比较R0 BM25、R1 BM25+dense RRF、R2 R1+适用性门控。评估Recall@5、nDCG@5、不适用注入率、空检索判断、实际延迟与成本。选出一个冻结方案进入问答主实验；检索标注成绩不是医疗准确率。若密集模型不能加载，显式报dense unavailable，不能把lexical_only结果写成R1/R2成功。

更强的图像向量检索留作后续B3：用同模态/视图的冻结影像编码器辅助E候选重排，仍注入文本Skill。先通过题干与任务筛选；不以视觉相似度直接推断相同诊断。它改变另一因素，不与首次K试验混跑。

## 5. 共同控制器：Skill驱动的补证与改答

所有实验组使用同一控制器，不复制其他论文的EDV–Director命名或算法。采用下列功能分解：

```python
w, initial = run_shared_unassisted_prefix(all_current_images, visible_question)
gaps = identify_discriminative_gaps(w, initial)  # no gold / explanation
k = retrieve_knowledge(gaps, w) if use_K else []
requirements = merge_requirements_without_inventing_patient_facts(gaps, k)
e = retrieve_and_check_skill(question_stem, requirements, w) if use_E else []
action = choose_action(requirements, e, available_tools, remaining_budget)
observations = execute_targeted_action_or_stop(action, w)
candidate = answer_with_current_observations(w, observations, k, e)
final = accept_or_retain(initial, candidate, w, observations, requirements)
log_initial_candidate_final_and_reasons()
```

第一轮最多一个定向补证动作＋一次候选审议，避免把更多预算误判为记忆收益。动作可以是原图定向复看、已有工具的匹配能力调用、替换工具、保留当前答案。参数必须围绕缺失属性而非“请证明某诊断”。分类工具无位置输出时不能支撑精确位置；同模态不同视图/时相必须各自查看。相关区域复看时发送全图＋ROI、方向和位置说明，不只发送裁剪图。

改答接受条件：候选相对初判的每个关键变化都有当前病例直接观察/题干事实支持；必要前提不缺失；关键矛盾已解决；没有仅凭检索案例诊断名覆盖图像。新知识可以纠正错误的解释规则而无需新图像，但必须指出“同一已有观察＋哪条有来源规则”为什么支持改答，不能仅因知识提到该疾病就通过。

证据不足则保留共同初判并标记unresolved；这不是宣称初判正确。也记录被拒绝候选，计算误拒有效纠正的数量。不得用gold、历史这题A是否正确、答案多数票或自报confidence决定接受。最多一次重新检索；反复找支持既有假设的资料不允许作为解决冲突的方式。

## 6. 主实验：保留B、C，不做庞大全因子组合

先对6个训练样本跑通controller、引用和条件拒绝；接着同一60题开发集运行下表。不要按题目历史对错分配组或决定是否注入。

| 组 | E经验 | K静态知识 | 对照问题 |
|---|---|---|---|
| N | 无 | 无 | 共同控制器/门控本身的基线 |
| B-E | B来源 | 无 | 题干检索+条件匹配的B经验 |
| C-E | C来源 | 无 | 有语义内容的C Skill |
| K | 无 | 有 | 单独知识的贡献 |
| B-EK | B来源 | 有 | 知识是否增益B并抑制其损害 |
| C-EK | C来源 | 有 | 知识是否增益C并保留C独有收益 |

每组60题，总360个续跑分支；共同前缀每题只采集一次。若已有完全同配置的N/B-E/C-E，可复用，只新增K/B-EK/C-EK的180个分支。历史A/B/C的初始prompt实验不是这种对照，不能直接冒充。共享初判以新共同前缀为准，不能偷看历史gold或强行复用旧答案作为推理状态。

组间固定：病例、全部图像、模型版本、采样配置、输出上限、动作集合、预算、门控、索引和提示模板。经验池首次B/C可以保留历史来源用于修复研究，记录规模/来源不同；需要证明Skill表示作用时，另用同一训练轨迹生成B/C表示，不能混为一谈。

K/E提示分别有预算，建议起点K最多800汉字等价字符、E最多900、合计最多1800字符；实际模型token另计。预算值为初始工程配置，不是论文规定。比较组允许有/无知识导致内容长度不同，报告实际成本；若出现提升，再补等token的无关但同风格知识对照，区分额外上下文与真实知识作用。

为了公平，共同前缀与相同工具参数的结果可缓存；参数或状态不同不得跨组复用。报告“完整逻辑成本”和“实际执行增量成本”两列。计时从真实事件时间戳计算，不用模型请求次数替代耗时。

## 7. 步骤信用与经验池进化

先让K/E工作，再单独增加步骤信用，避免首轮同时改变所有因素。训练集选20个代表性checkpoint，固定其全部图像、W和已获工具输出；do/skip两分支，各3个配对随机重复，共120个续跑。能力允许时再加入替代动作，另记成本。

键必须为`checkpoint_id + candidate_action_id + repeat_id + model/config_version`；不能按数组下标配对、不能只按task/capability混合不同题目。do与skip共享截止状态；do的新增结果在skip不可见。回放必须真正向VLM发送当前图像，不能把图像路径只放授权字段而实际文本调用。

主信用为配对正确率差及置信区间；次指标为新增可用证据、遗漏减少、耗时/工具/token费用。轨迹成功不等于每步有功，失败也可能含有效步骤；一次差值不足时保留unknown。LLM对步骤的合理性评分只能作为审阅特征，不能伪称因果贡献。

每个Skill保留适用条件、需要的信息、推荐动作、检查点、失败分支、停止条件、step_credit（estimate/n/uncertainty/status）。先优先检索有支持的成功动作；失败经验以“触发条件＋不要重复什么＋替代动作”表示，禁止将失败答案写成推荐结论。K的医学命题不参与答对奖励更新。

有限容量试验放在确定短期有效后：E容量先固定128，再比较64/256；条件相同且动作等价的条目去重，保留高覆盖、高可信、有互补失败边界的代表。冗余淘汰按任务/模态/缺口分桶，保护稀有但有用经验；不能全局仅按频次删掉难题经验。容量结果报告覆盖、纠正/损害、池稳定性和检索时间，不只最终准确率。

## 8. 必报结果与选择规则

每组输出相对共同初判的corrected、harmed、unchanged_correct、unchanged_wrong、execution_failed，以及净增益 `(corrected-harmed)/N`。失败按预注册intention-to-treat口径计入分母；另给共同完成样本分析，不能悄悄删除失败。

所有组同时对比历史B/C：共同收益5题、B独有3题、C独有3题的保留；共同损害6题、B独有3题、C独有8题的变化。这些只是开发追踪，不能把历史对错用于控制器输入。分类型、单/多图、定位/关系/比较分别报告。完整28题状态见经验文档。

门控报告：无门控候选纠正数、候选损害数、最终纠正数、最终损害数、有效纠正保留率、候选损害阻止率、误拒纠正数、错误接受数。候选与门控结果共享一次生成，不另做不必要的新模型实验。

知识报告：检索覆盖、被拒绝原因、前提未知/不满足、引用是否支持规则、是否存在“知识变成患者事实”、实际完成的补证动作及其结果。延迟报告每题墙钟中位数/P90，另报token、模型和工具次数、费用。

60题上的开发选择：首先净增益大且损害可控，再比较纠正保留和成本；同时给病例配对bootstrap区间与配对检验，不凭1题波动宣布胜利。冻结选中版本、阈值、索引和容量后，在未用于设计的独立测试病例上评估；不能再把这60题叫最终测试。允许保留无知识或无经验方案为优胜者，不强行证明新方案有效。

跨数据验证只迁移公共K和训练Skill，不搬入目标测试案例。优先选仍为胸部影像、且任务形式可对齐的独立VQA/报告问答子集；按患者/病例划分，重新校验标签映射与图片可用性，先小样本接通再冻结评估。外部任务不支持现有工具时，以共有动作集比较；不同数据集的分数不合并为单一涨点。

## 9. 接入与交付检查表（仅方案验证）

- 把 `knowledge/clinical_cards.jsonl` 和 `knowledge/source_pages.jsonl` 注册为显式白名单；索引器不递归扫描整个下载包。
- 为 E 适配旧记录，查询端与索引端同步题干化；把“检索命中”和“真正注入”的列表分开。
- 把K/E接入每题共同checkpoint之后；所有图片保留到实际VLM请求。
- 按image/entity/timepoint比较矛盾；不要把不同图片/时间的不同观察误判冲突。
- 结果文件最少包含`qid,group,initial,candidate,final,gold_eval_only,correct,changed,gate_reason,knowledge_ids,experience_ids,action,observations,latency,cost,status`。gold只在评估后写入隔离结果，不参与运行函数。
- 输出配对表和失败清单；明确已完成/未完成组数。没有实际跑完的组不能填估计分数。

完成标准：运行可复现，因果对照清楚，能回答“静态知识带来了哪些纠正，又新增/阻止了哪些损害”。即使没有涨点也应交付可解释结果，不能只交平均分或挑成功案例。
