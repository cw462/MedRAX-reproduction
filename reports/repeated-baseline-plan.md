# Prepared repeated-baseline analysis plan — not executed

**Status: preparatory infrastructure only, never executed, superseded by V3.** V3 P1.1 instead requires a preselected validation sample of at least 30 questions with single/multiple-image coverage. The first-ten classifier-only design below is retained as an unexecuted historical plan and is not a full MedRAX Agent comparison. A later experiment requires its own frozen manifest; results must not be relabeled as though the sample or tools were unchanged.

The unfinished, untested scorer draft for this superseded design is retained only in the private preparation workspace and is not shipped as usable evaluation code. The analysis below records design intent, not validated scorer functionality or an executed experiment.

The prepared design uses the first ten distinct cases in the original frozen 50-question inference order, without selecting on truncation, predictions or correctness. It crosses output caps 512/1024, three repeats, and direct/classifier-only Agent: 120 planned arm outcomes. Within each repeat/question block, the four cap/arm combinations are shuffled using seed 20261027. This seed determines order only; it does not control provider randomness. Six slice journals and one global journal retain failures and all planned denominators. The existing budget and global stop rules apply.

## Analysis fixed before any new outcomes

- Score only finalized run artifacts after validating manifest, schedule, slice/root journals and the finalization marker. By default require completion; an explicit stopped-run analysis retains every missing outcome as unrun in the 120-outcome plan. Labels are opened only after these checks. Inference and traces receive no labels.
- Report each cap/arm/repeat accuracy with denominator ten, including errors, invalid answers and unrun outcomes as not correct. Report the three-repeat range as descriptive variability, not a confidence interval.
- For A/A stability, compare repeats 1–2, 1–3 and 2–3 within the same cap, arm and case. There are 30 planned pairs per cap/arm. Report identical valid predictions, valid prediction flips, and pairs missing a valid answer separately, using the fixed 30 denominator and the valid-pair denominator explicitly. Two failures do not count as agreement. Also report cases with any valid flip and all-three-valid-identical predictions. Prediction flips need not be correctness flips.
- Average correctness over the three repeats **within each case**. The cap contrast is the mean across ten cases of `mean(correct at 1024) − mean(correct at 512)`, separately for each arm. A secondary contrast compares Agent minus direct within each cap using the same averaging. Bootstrap ten case units with replacement, retaining all repeats/conditions together; use 10,000 resamples, seed 20261027 and percentile 95% intervals. Repeated requests are not independent cases. No confirmatory significance claim or multiple-endpoint success rule is specified.
- Report truncation, API errors, malformed tool calls, calls, observed token usage and unknown usage. Check actual execution order against the seeded plan, report wall-clock bounds and per-condition latency descriptively, and distinguish requested/returned model identity from verification of underlying weights. Reservation blocks are not API requests.

This is repeated development-set research, not held-out evaluation, representative sampling, patient independence or a causal guarantee. Temperature-driven variation, proxy/provider changes and time effects remain possible explanations. Do not combine these outcomes with earlier selectively rerun cases to revise a frozen baseline score. Public summaries contain aggregate metrics and permitted question-ID indices only; no answer letters, original questions, reports or model reasoning.

## Full-tool readiness before a replacement comparison

At least the six diagnostic tools must each have separate real-call evidence: `ChestXRayClassifierTool`, `ChestXRaySegmentationTool`, `LlavaMedTool`, `XRayVQATool`, `ChestXRayReportGeneratorTool`, and `XRayPhraseGroundingTool`. Record exact source/model revisions, weight/config hashes, approved development image hashes, real execution status, output-schema checks, duration and artifact hashes. A loaded module, mock output, nonempty text or schema-valid return alone does not establish clinical correctness.

Then verify Agent-generated tool selections and arguments, real invocation/observation pairs, allowed-image boundaries, and a final response in a dynamically chosen trajectory. All selected tools must share the per-case call/time budget, with every paid model request guarded by the shared monetary ledger. Raw reports may be consumed by the Agent but must not enter public traces or reports. Keep execution verification distinct from unknown clinical evidence.

Availability and individual readiness are tested separately from task utility: **do not force every question to call all six tools**. In a subsequent full-Agent versus direct comparison, freeze the same six-tool availability for every full-Agent condition while matching question/image bytes, backbone model, sampling, output cap and final-answer protocol across the direct and Agent arms. The direct arm remains explicitly tool-free; a tool-enabled control would be a separately named arm. Freeze this replacement design and its budgets before running it. No held-out labels are used during readiness or development.
